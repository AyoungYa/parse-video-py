## 微博解析报错定位 + Cookie 支持（本次交付）

### 报错根因（`Exception: parse weibo html page fail`）
- 用户 URL 是**微博用户主页弹层链接**（`weibo.com/n/<昵称>?tabtype=newVideo&layerid=...`），
  按 `weibo.py:26-31` 逻辑 `post_id = path_parts[-1]` → 取到的是**昵称**而非 mid，属于错误输入。
- 实测证据：`GET` 该 URL 返回 **302 → `passport.weibo.com/visitor/visitor`（Sina Visitor System）**，
  页面无 `$render_data` → `_parse_html_page` 必然抛异常。**未带 Cookie 会被访客风控拦截**。
- 另一条链路 `m.weibo.cn/statuses/show?id=<mid>` **实测可用**（返回完整 json，含 pics）。
- 诊断黑洞：原 `weibo.py:89` 的 `except Exception: pass` 静默吞掉 mobile API 失败原因。
- 附带告警 `Error occurred during getting browser: random...` 是 fake_useragent 拉取 UA 列表失败降级本地缓存，**无害**。

| `parser/weibo.py` | `parse_post_url` / `parse_video_id` 注入 Cookie；移除 `except: pass` 改为记录 `mobile_error`；检测到重定向到 `passport.weibo.com`/`visitor` 时抛**明确提示**（含 mobile 失败原因） |

### 用法（用户传入 Cookie）
```bash
export PARSE_VIDEO_WEIBO_COOKIE='SUB=xxx; SUBP=xxx; SSOLoginState=xxx'
# 浏览器 F12 → Network → 任意微博请求 → Request Headers → Cookie 整串复制
PYTHONPATH=src python src/parse_video_py/test/test1.py "<微博链接>"
```
- **注意**：Cookie 走环境变量，**禁止硬编码**（符合知识库「禁止硬编码密钥」规则）。
- 单条微博链接（`weibo.com/<uid>/<mid>`）**通常无需 Cookie**，mobile API 直接可通（实测 10 张图解析成功）。

## 【重要纠正】uvicorn 模块路径写法（推翻 10-14 的结论）
- **10-14 我判断"`web.py` 内部用 `from src.parse_video_py import ...`，所以必须写 `src.parse_video_py.web:app`" —— 该结论已过期/错误。**
- 现状实测：`web.py:13-14` 已是 **`from parse_video_py.parser import ...`（无 `src.` 前缀）**。
- 实测四种组合结论：
  - 无 PYTHONPATH + `src.` 前缀 → ❌ `ModuleNotFoundError: No module named 'parse_video_py'`（A 组）
  - 无 PYTHONPATH + 无前缀 → ❌ 同样失败（B 组）
  - **`PYTHONPATH=src` + 无前缀 → ✅ OK**（C 组）
  - **pip 可编辑安装 `-e ".[all]"` 后，任意目录 + 无前缀 → ✅ OK**（D 组）
- **正确姿势（README 已按此描述）**：先 `uv pip install -e ".[all]"`，然后在项目根目录执行
  `uvicorn parse_video_py.web:app --reload`。实测启动成功、`GET /` = HTTP 200。
- 另：`cli/__init__.py:51` 的 `uvicorn.run("parse_video_py.web:app", ...)` 也是无前缀写法，**与现状一致，不用改**。
