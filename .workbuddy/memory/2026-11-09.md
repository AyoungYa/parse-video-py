## cloud_web 的 PyCharm 调试配置（新建 8 个 run configuration + 独立模块）

需求：给 `cloud_web`（云端 Django 服务）建 PyCharm 调试配置。
做法：新建 **独立模块 `cloud_web`**（`.idea/cloud_web.iml` + `modules.xml`），
8 个 run configuration 全部**真跑验证过**，并写了 `cloud_web/DEBUG.md` 说明。

### 为什么必须独立模块

项目根模块 `parse-video-py` 用 conda `~/miniconda3/envs/parse-video-py`，
**那里面没装 Django**（`import django` → ModuleNotFoundError）；
`cloud_web` 的依赖在 `cloud_web/.venv`（django 5.2.19 / DRF / oss2 / pymysql）。
→ 拆成两模块，各用各的解释器。

★★ **run configuration 里用 `SDK_HOME=$PROJECT_DIR$/cloud_web/.venv/bin/python` 显式指路径**，
不依赖 IDE 里是否注册了名为 `cloud_web` 的 SDK（换机器/换 IDE 版本都能跑）；
`SDK_NAME` 仍填已存在的 `parse-video-py`，只为了让 PyCharm 不报「解释器未找到」。
★ 模块的 `orderEntry jdkName` 也填 `parse-video-py`（填不存在的名字会红）。

### 三个必须记住的坑

① **`DJANGO_SETTINGS_MODULE` 显式给 `dev`** —— `prod.py` 开 `SECURE_SSL_REDIRECT=1`+HSTS，
   本地跑 301 死循环。
② **单测用 `config.settings.test_local`（不是 dev）** —— 两个原因：
   `dev.py` 强制校验 `MYSQL_PASSWORD` 非空（本地 root 空密码会被挡）；
   ★★ `base.py` 的 `load_dotenv` 会把 `.env` 里**远程调试库**的
   `120.25.1.236` / `test_db_rw` / 密码注入环境变量 → `test_local.py` 必须
   **写死**本机 3307 参数 + 强制空密码（副作用是好的：本地单测永不误连远程库）。
   ★ 之前 `test_local.py` 写 `os.getenv("MYSQL_HOST", "127.0.0.1")` 是**错的** ——
   getenv 拿到的是 .env 注入的远程值 → (1045) Access denied for 'root'@'localhost'。
③ **`run_worker` 前必须先 migrate** —— `gpu_worker` 用**本地 SQLite**（worker.sqlite3），
   首次跑直接崩 `no such table: local_task`。且需 `WORKER_TOKEN`
   （云端 `create_worker` 生成，只显示一次）→ 缺了报清晰的 RuntimeError。
