## 二、工作分解（WBS）

### M1 · 管线自动化（最难，先啃）—— 7 人日

把「调参台的人工决策」固化为自动流程：

```
上传 → 自动定位 → 自动建 mask（min>100 柔边口径）
     → 自动渲染 → 自动验收（四层残留 + σ比 + 帧间差）
     → 决策树：全绿→交付 | σ<0.8→texture_fix | 条带断裂→rowfill | 仍不过→转人工确认
     → 生成报告页
```

- 1.5d 自动定位封装 + 降级策略（定位失败→引导用户拖框，复用现有交互）
- 1.5d 渲染→验收→修复的 pipeline 编排（jobs.py 扩展多阶段任务）
- 2d 决策树实现（阈值来自现有踩坑手册，直接代码化）
- 2d **语料回归测试**：攒 20~30 条不同背景/分辨率/水印类型的样片跑全绿率
  （这是北极星指标 ≥90% 的前置，不能省）

### M2 · 多用户基础 —— 4 人日

- 1d 用户表/任务表/积分账本从 jobs.json 迁移到 MySQL（远程实例，本地与线上同库结构）
- 1.5d 注册登录（微信扫码优先 + 手机号兜底）+ 会话
- 1d 上传服务（≤500MB、格式白名单、临时存储即删）
- 0.5d 任务按用户隔离 + 并发限流

### M3 · 三步流前端 —— 3 人日

- 剥离 wm_index.html 的调参 UI → 上传页 / 确认页（mask 可视化 + 可拖框兜底）/ 交付页
- A/B 对比组件保留（这是卖点展示位）
- 报告页（指标绿灯 + 前后对比截图）

### M4 · 计费 —— 5 人日

- 1.5d 积分账本 + 消耗规则（免费试用 3 条 × ≤30s、签到 +1、连签 +5、**月累计封顶 10 分**、月度清零）
- 1d 签到 + 余额页
- 2d 微信支付（Native 扫码 + H5）+ 订阅开通/续费/回落状态机
- 0.5d 防滥用（设备指纹粗筛 + 同号限领 + **用量上限 100min/月 硬闸门**）

### M5 · 部署上线 —— 6 人日

**目标环境（已定，见 `成本与选型.md` / `算力部署方案.md`）**：
- Web/API/队列/交付页：阿里云轻量应用服务器 **2核4G**（¥379/年，200M 峰值不限流量）——**必须已备案**
- 渲染算力：**本地优先** —— 开发期 Mac（MPS），正式期自建单卡 4090 PC
- 存储：OSS 标准存储 + 临时区 TTL 24h 自动删

- **2.5d 本地 worker 接入**（新增，见 `算力部署方案.md` §2/§3）
  - `Job` 增加 `dispatching/leased` 状态 + `worker_id/lease_expires/attempt` 字段
  - 5 个端点：`/upload/sign`（给前端签直传 URL）、`/worker/claim`（25s 长轮询）、`/worker/heartbeat`、`/worker/complete`、`/worker/fail`
  - `worker.py` daemon：出站长轮询领任务 → OSS 签名 URL 下载 → 调渲染 → 心跳续租 → 成片回传 → 上报完成+指标
  - **租约回收定时任务**（90s 超时打回 pending，`attempt>=3` 判失败告警）——防断电占死任务
  - workspace 路径映射 + 开机自启（launchd / systemd / 任务计划）
- 1d 域名/HTTPS + 监控告警（**队列积压、租约超时次数、失败率、每分钟处理成本**）
- 1d 压测（并发回传限 1、串行队列吞吐）+ 灰度开关 + **标定 PC GPU 真实 LaMa fps**
  （这个实测值直接决定包月上限，见 `成本与选型.md` 第七节）
- 0.5d 用户协议/隐私页（处理完即删的承诺落成定时任务）
- 1d 可靠性兜底（worker 离线时的前端「预计等待」提示 + 运营告警）
- ~~云 GPU 部署~~ 推迟到触发门槛（见 `算力部署方案.md` §6），不占本期工期

**合计：25 人日（M1 与 M2 可并行 → 日历约 5 周）**

> M5 里「本地 worker 接入」是**唯一因「算力放本地」新增的开发量**（2.5 人日）。
> 如果跳过 worker 化、只在开发期用单机全栈，能省这 2.5 天，但**正式对外时绕不过去**——
> 家宽不能对外提供 Web 服务和备案，云 Web + 本地 worker 是唯一合规路。建议一次做到位。

## 五、关键风险与对策

| 风险 | 概率 | 对策 |
|------|------|------|
| 全绿率达不到 90%（自动决策树覆盖不了野片） | 中 | M1 的 1d 预留迭代；兜底策略=转人工框选而非硬交付 |
| 队列在免费流量下积压 | 中 | 免费档限 ≤30s + 每日总量闸门；队列积压监控自动关免费入口 |
| 微信支付/备案拖延上线日 | 高 | 两条长杆今天启动；付费可后置——GA 先积分制，支付模块 rc 后插拔上线 |
| 大文件上传失败率高 | 低 | 分片上传 + 断点续传；500MB 上限 |
| **LaMa 实测吞吐远低于规划值** | 中 | Mac 有参考值（4.8fps @1080P ROI），**PC 的 GPU 必须实测**。若远低于规划，成本上升 → 包月上限从 100min 下调。**M5 压测必须标定，且产品文案先不写死上限数字** |
| **PC 无 N 卡 / 显存不足（体检未做）** | 中 | 先跑 `nvidia-smi` 再装环境。不合格则渲染回退 Mac（MPS 可用，全片 5.5 分钟可接受），PC 转备用角色 |
| **免费/签到额度被刷** | 中 | 签到月封顶 10 分 + 手机号验证 + 设备指纹；预算监控按日告警 |
| **★ 本地 worker 失联（断电/断网/系统更新重启）** | **高** | 任务租约 90s 超时回收 + `attempt>=3` 告警；worker 开机自启 + 崩溃重启守护；前端显示「预计等待」而非假装处理中；**GA 前做一次断电演练** |
| **家宽上行被成片回传堵死** | 中 | 并发回传硬限 1；4K 单条时长限制更严；必要时办上行提速包（100Mbps） |
| **本地算力无法承诺 SLA** | 中 | 产品文案不承诺可用性；B 端客户要求 SLA 时才上云（触发门槛已量化） |
