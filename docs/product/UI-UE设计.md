> 版本 2026-11-04 · 对应 `cloud_web/frontend`
> 前置文档：`商业化方案.md`（定位与付费）、`架构设计.md`（服务边界）

---

## 一、设计目标：先解决"不信任"，再谈好看

去水印用户的核心心理不是"想玩个工具"，而是**"我有一条值钱的素材，怕白折腾"**。三类恐惧按强度排序：

| 恐惧 | 用户原话 | 现有竞品怎么做 | 我们怎么做 |
|------|---------|--------------|-----------|
| **怕处理完还有痕** | "上次那个擦完留一圈白边" | 处理完直接给下载，用户自己赌 | **A/B 对比 + 局部放大 + 三项验收指标**，摆在下载按钮前面 |
| **怕白传一遍** | "传了 5 分钟才告诉我不支持" | 传完才校验 | **选片后本地预检**，不合格当场拦，一个字节都不传 |
| **怕等得不明不白** | "到底卡在哪了" | 一根假的 99% 进度条 | **四阶段时间线**，每个阶段真实、可解释、可取消 |

三条 UE 原则由上面推导出来：

1. **前置判断**——能在本地判定的事，绝不留给服务端拒绝
2. **证据优先**——结论要用画面证明，不用文字承诺
3. **状态诚实**——宁可显示"算力机离线，预计 3 分钟"，不显示虚假进度

## 二、一个关键流程改造：选片即预检

现有流程（要改）：

```
选文件 → 直接上传 500MB → 排队 → 云函数校验 → 失败 → 用户白等
```

新流程：

```
选文件 → 本地 200ms 预检 → 展示体检卡 → 用户确认 → 才上传
```

**预检项**（全部在前端完成，零请求）：

| 检查 | 手段 | 不合格提示 |
|------|------|-----------|
| 格式 | `file.type` + 扩展名白名单 | "暂不支持该格式，请转成 mp4 再试" |
| 大小 | `file.size ≤ 500MB` | "文件 620MB 超过 500MB，可先在剪辑软件里压一下" |
| 时长 | `<video>` metadata 读 duration | "这条 42s，试用版限 30s"（升级/裁剪二选一） |
| 画面尺寸 | `videoWidth/Height` | 展示"竖屏 1080×1920"，让用户确认没选错片 |
| 水印粗定位 | 抽首帧画到 canvas，四角方差分析 | "检测到右上角疑似水印"——提前给预期 |

预检卡不是拦人，是**把不确定性提前暴露**。合格也展示，因为"检测到右上角水印，预计消耗 1 积分"本身就降低了焦虑。

> 这一步的商业价值：无效上传直接归零，省的是用户流量 + 我们的 OSS 流量费 + GPU 空转。

## 三、信息架构

```
/                 工作台      上传（视觉主体）+ 最近 3 条任务
/tasks/:id        任务详情    处理中 / 已完成 / 失败 —— 同一个页，状态驱动
/points           账户        积分、签到、流水、订阅（第二期加支付）
/login            登录注册
```

**刻意不做的页面**：独立"任务列表"页。用户日活通常只有 1~3 条任务，工作台下方横条足够；等单用户月任务 > 20 条再加。

顶栏只放四件：品牌、积分胶囊、账户、退出。**不放导航菜单**——三个页面的产品，菜单是负担。

## 四、设计系统

### 4.1 色彩：墨与纸

概念取自"匠"——**不炫技，但要经得起细看**。拒绝渐变、玻璃拟态、发光边框，那些是娱乐 App 的语言；工具应当是纸、墨、刻度。

| 变量 | 值 | 用途 |
|------|-----|------|
| `--ink-900` | `#121A17` | 主文字（带一丝绿的黑，避免死板纯黑） |
| `--ink-600` | `#4C5754` | 次要文字 |
| `--ink-400` | `#8A938F` | 辅助说明、占位 |
| `--line` | `#E4E3DD` | 卡片描边、分割线 |
| `--line-soft` | `#F0EFE9` | 更弱的分割（表格行） |
| `--paper` | `#FAF9F5` | 页面底色（米白，衬出白色卡片） |
| `--surface` | `#FFFFFF` | 卡片 |
| **`--brand`** | **`#0E5C4A`** | **主按钮、链接、当前态（深墨绿）** |
| `--brand-hover` | `#0A4739` | hover |
| `--brand-wash` | `#EAF4F0` | 选中背景、标签底 |
| `--ok` | `#12946A` | 指标达标（亮一档，与品牌色拉开明度差） |
| `--bad` | `#D14B4B` | 指标不达标 |
| `--warn` | `#BC7209` | 需留意 |

> **为什么品牌色和"达标绿"要分两档**：品牌色是深墨绿（近黑），语义绿是亮绿。同色系不同明度，视觉上不会混，情绪上又统一——"干净"是这个产品从品牌到指标贯穿到底的隐喻。

### 4.2 字体

系统字体栈（不引外链字体，首屏零等待）：

```
-apple-system, "PingFang SC", "Microsoft YaHei", "Segoe UI", sans-serif
```

| 层级 | 大小 / 行高 | 字重 | 用在哪 |
|------|-----------|------|--------|
| display | 30 / 1.2 | 500 | 登录页主标题、结果页结论 |
| h1 | 22 / 1.35 | 500 | 页面标题 |
| h2 | 16 / 1.5 | 500 | 区块标题 |
| body | 14 / 1.65 | 400 | 正文 |
| small | 13 / 1.6 | 400 | 说明 |
| micro | 12 / 1.5 | 400 | 标签、脚注 |

**数字一律 `font-variant-numeric: tabular-nums`**——验收指标是小数，等宽数字才不会跳动，这是"专业"最便宜的来源。

### 4.3 间距与几何

- 间距基数 4px，只用 `4 / 8 / 12 / 16 / 24 / 32 / 48`
- 圆角：卡片 `14px`、按钮与输入 `10px`、标签 `6px`、胶囊 `999px`
- 阴影：只用一层极轻的浮起，`0 1px 2px rgba(18,26,23,.04), 0 6px 20px -8px rgba(18,26,23,.08)`
- 内容最大宽 `880px`（比原来的 760px 宽——结果页要放得下对比视图），左右留白 20px

### 4.4 组件规范

**按钮**
| 类型 | 样式 | 用途 |
|------|------|------|
| primary | 深墨绿底白字，高 44，圆角 10 | 一屏只能有一个：上传/下载 |
| secondary | 白底 + 1px 描边 | 次要动作 |
| ghost | 无底无边，hover 出 `--brand-wash` | 取消、切换 |

**卡片**：白底 + 1px `--line` + 14 圆角 + padding 20~24。一屏不超过 3 张，超过说明该拆页了。

**状态徽标**：`wash 底 + 600 系文字`，高度 22，圆角 6，字号 12。
排队=灰、处理中=墨绿、全绿=亮绿、需留意=琥珀、失败=红。

## 五、关键页面

### 5.1 工作台 `/`

```
┌────────────────────────────────────────────┐
│ 无痕匠                      积分 12  ○豆豆 │
├────────────────────────────────────────────┤
│                                            │
│  把水印擦干净，然后给你一份验收单            │   ← display
│  上传你自己的素材，处理完附残留/纹理/闪烁三项检测  │
│                                            │
│  ┌──────────────────────────────────────┐  │
│  │        [虚线区 + 图标]                │  │
│  │    拖入视频，或点击选择                │  │  ← 点击/拖拽/粘贴 三种入口
│  │    mp4 mov avi mkv · ≤500MB · ≤30s   │  │
│  └──────────────────────────────────────┘  │
│                                            │
│  最近任务 ───────────────────────────       │
│  [缩略图 已完成 ✓] [缩略图 处理中 62%]      │
│                                            │
└────────────────────────────────────────────┘
```

细节：
- 上传区**空态高 260px**，拖拽进入时整块变 `--brand-wash` + 描边转实线，有明确的"松手即传"提示
- 支持**粘贴上传**（Ctrl+V 直接贴视频文件）——做视频的人常从聊天窗口复制，这是低成本高感知
- 未登录时上传区上方出现"登录后送 3 条试用"的细条，点击去登录

### 5.2 预检卡（选片后、上传前）

```
┌──────────────────────────────────────────────┐
│ [缩略图]  weibo_261021.mp4          14.2 秒  │
│           竖屏 1080×1920 · 86 MB             │
│ ──────────────────────────────────────────── │
│ ✓ 格式与大小符合    ✓ 时长在试用额度内        │
│ ● 检测到右上角疑似水印                        │
│ ──────────────────────────────────────────── │
│ 预计消耗 1 积分        [ 取消 ]  [ 开始处理 ] │
└──────────────────────────────────────────────┘
```

预检结果用三态：`✓ 通过`（墨绿）/ `● 提示`（琥珀）/ `✕ 拦截`（红）。**拦截时主按钮变成"换一个文件"，不给用户点进去撞墙的机会。**

### 5.3 任务详情 · 处理中

```
状态徽标：处理中                          再传一条
weibo_261021.mp4 · 14.2 秒

┌──────────────────────────────────────────┐
│  ● 排队等待        已完成                 │
│  │                                       │
│  ● 定位水印        已完成                 │
│  │                                       │
│  ◉ 修复画面        进行中 · 62%          │  ← 只有这一段有进度条
│  │                                       │
│  ○ 质量验收        待开始                 │
└──────────────────────────────────────────┘
       预计还需 40 秒 · 取消并退还积分
```

**为什么拆四段而不是一根条**：一根条 37% 时用户完全无法判断还要多久、卡没卡。四段里已完成的打勾，用户立刻知道"主体工作在跑，快好了"。

真实原因要露出来：
- 排队 → "正在等待算力节点，前面还有 2 条"
- 节点离线 → 琥珀提示条："处理节点暂时离线，任务已自动重新排队，**不需要重新上传**"
- 单条 > 2 分钟 → 补一句"长度或水印面积较大的片子会慢一些"

### 5.4 任务详情 · 已完成（核心页）

```
┌──────────────────────────────────────────┐
│ 已完成  ✓ 三项全部通过      再传一条      │
├──────────────────────────────────────────┤
│  ┌────────────────────────────────────┐  │
│  │         [原片 │ 成片]              │  │  ← 拖动分割线对比
│  │          ← 可拖动 →               │  │
│  └────────────────────────────────────┘  │
│  [ 原片 ] [ 成片 ]  [ 放大看水印位置 ⌕ ]  │
├──────────────────────────────────────────┤
│  验收报告                                 │
│  ● 残留        0.42 / 及格 3.0   几乎为零 │
│  ● 纹理自然度  1.03 / 及格 0.85  与周边一致│
│  ● 帧间闪烁    0.31 / 及格 1.5   无闪烁   │
│  任何一项不达标，本次不计费                │
├──────────────────────────────────────────┤
│  [ 下载成片 ]   [ 报告 JSON ]             │
│  链接 10 分钟有效 · 成片 24 小时后删除     │
└──────────────────────────────────────────┘
```

三个刻意的设计：

1. **对比视图是首屏主体**，下载按钮在报告下方——用户的决策是"看完再下"，把顺序做对，他会更愿意付费
2. **指标给三段信息**：名称 + "实测值 / 及格线" + 一句人话结论。只给 `0.42` 用户无感，给"几乎为零"他才有感
3. **"不达标不计费"写在报告卡里，不在协议里**——这是竞品不敢写的话，写出来就是护城河

### 5.5 账户 `/points`

- 积分余额做成大数字（40px），下方一行"约可处理 4 条 30 秒视频"——**把积分翻译成用户能理解的东西**
- 签到按钮有连签进度：`● ● ● ● ○ ○ ○` 七个点，第 7 天标"+5"
- 流水按日期分组，消耗用 `--ink`，获得用 `--ok`

### 5.6 登录

左 40% 是品牌区（米白 + 一句 slogan + 一行合规声明），右 60% 表单。移动端折叠成单列，品牌区只留 logo。

**合规声明放在首屏可见处**，不塞进页脚：
> 仅限处理您拥有版权或已获授权的素材。本站不提供任何平台视频解析或下载功能。

## 六、状态设计矩阵（最容易漏的部分）

| 场景 | 设计 |
|------|------|
| 首次进入（0 任务） | 上传区下方不是空白，放"什么样的片子效果最好"三条示例说明 |
| 上传中 | 显示真实字节进度 + 可取消；上传完不跳页，原地转"已提交"再跳 |
| 上传失败 | 保留已选文件，给"重试"，不用重选 |
| 队列为空且算力机离线 | 琥珀条 + "已为你排队，节点上线后自动开始"；**不报错** |
| 定位失败 | "没能自动确认水印位置" → 收一个"手动框选"入口（第二期实现，先占位并说明） |
| 指标有 1 项不达标 | 不隐藏、不模糊措辞。标琥珀 + "该位置可能有轻微痕迹，建议放大确认" + 免费重跑一次 |
| 任务过期（>24h） | "素材已清理，可重新处理" —— 提供一键重跑，避免重传 |
| 积分不足 | 不弹窗打断，在预检卡里直接显示"积分不足，签到或订阅" |

## 八、实现约定

- **设计 token 全部在 `src/styles/tokens.css`**，页面里不写死颜色，只引用变量
- Element Plus 仅保留 toast（`ElMessage`），其余控件自研——它的默认圆角和阴影会破坏品牌一致性
- 图标全部用内联 SVG（12 个以内），不引图标库，省 200KB
- 首屏不加载 Element Plus 全量 CSS 以外的任何第三方 UI
- 所有图片走 OSS 缩略图（`x-oss-process=image/resize,w_320`），列表页不加载原图
