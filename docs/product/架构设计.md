# 无痕匠 · 系统架构设计

> 2026-11-04。本文是**代码实现依据**，两份可独立部署的服务：  
> `cloud_web/`（云服务器，Django + Vue + MySQL + OSS）与 `gpu_worker/`（算力机，Django）。  
> 商业与成本背景见 `商业化方案.md` / `成本与选型.md` / `算力部署方案.md`。

## 一、部署拓扑

```
                    ┌──────────────────────────────────────────┐
   浏览器 ─────────▶│  云服务器（阿里云轻量 2核4G，已备案）        │
   （Vue SPA）      │  Nginx → Django(DRF) + Vue 静态资源        │
        │           │  MySQL 8（同机起步）                       │
        │           └───────┬──────────────────────┬───────────┘
        │  ① 直传原片        │ ③ 长轮询领任务        │ ⑦ 完成回调
        │  (PostObject)     │                      │
        ▼                   ▼                      │
   ┌─────────┐      ┌──────────────────────────────┴─────────┐
   │   OSS   │◀────▶│  算力机（豆豆的 PC，NAT 后，无公网入口）   │
   │ 临时区   │ ⑤⑥   │  Django + 常驻管理命令 run_worker        │
   └─────────┘      │  → 本地 LaMa / texture_fix / verify      │
```

**唯一的网络方向**：算力机**只发起出站 HTTPS**（去云 API 领任务、去 OSS 取/传文件）。云端从不主动连算力机，因此不需要内网穿透、不需要公网 IP、不需要开入站端口。

## 二、两个服务的职责边界

| 维度       | `cloud_web`（云）                           | `gpu_worker`（算力机）                   |
| -------- | ---------------------------------------- | ----------------------------------- |
| 用户交互     | ✅ 全部（注册登录、上传、进度、下载、计费）                   | ❌                                   |
| 任务队列与状态机 | ✅ 唯一权威（云端 MySQL）                       | ❌ 仅本机任务镜像与阶段日志（独立 MySQL 库）      |
| 视频文件     | ❌ 不落盘、不中转                                | ✅ 临时下载到本地 workspace，处理完删            |
| 推理算力     | ❌ 不跑任何模型                                 | ✅ 全部                                |
| 鉴权       | 签发用户 token、校验 worker token、签发 OSS 临时 URL | 持有一个 worker token（长期），不接触 OSS AK/SK |
| 可用性要求    | 高（对外）                                    | 低（单点，可离线，任务靠租约兜底）                   |

**一句话**：云端是「大脑 + 账本」，算力机是「可随时离线的工人」。

## 四、任务状态机

```
[创建任务]
    │  用户浏览器直传 OSS 成功
    ▼
awaiting_upload ──确认上传──▶ pending ──领取──▶ leased
                                ▲                    │
                                │                    ▼
                                │           extracting_frames ──▶ locating_watermark
                                │                                      │
                                │                                      ▼
                                │                           awaiting_confirmation
                                │                           （关键帧 + 红色建议框）
                                │                                      │ 用户确认或调整框
                                └──────────────────────────────────────┘
                                │
                                └──再领取──▶ leased ──▶ removing_watermark ──▶ verifying ──▶ succeeded

在途租约超时或可重试错误回 pending；重试耗尽进入 failed。用户可在待确认阶段取消。
```

| 状态                | 含义                   | 谁能改            |
| ----------------- | -------------------- | -------------- |
| `awaiting_upload` | 已建单，等浏览器上传完成回调       | 用户 API         |
| `pending`         | 可被领取                 | 系统             |
| `leased`          | 已被某 worker 领取，锁 90 秒 | worker（心跳续租）   |
| `extracting_frames` | 下载原片并提取预览关键帧 | worker |
| `locating_watermark` | 分析抽样帧，给出水印位置和大小 | worker |
| `awaiting_confirmation` | 展示关键帧和建议红框，等待用户确认或手动调整 | worker / 用户 API |
| `removing_watermark` | 按用户确认的区域逐帧去水印 | worker |
| `running`         | 兼容旧任务的处理中状态       | worker         |
| `verifying`       | 跑验收指标                | worker         |
| `succeeded`       | 成片就绪 + 指标全绿          | worker 上报      |
| `failed`          | 失败（含重试耗尽）            | worker 上报 / 系统 |
| `cancelled`       | 用户主动取消 / 退款          | 用户 API         |
| `expired`         | 未上传任务过期          | 定时任务           |

**租约是核心**：`leased` 状态带 `lease_expires_at`，worker 每 15 秒心跳续到 90 秒后。定时任务每 30 秒扫一次超时的 `leased` → 打回 `pending` 并 `attempt += 1`。`attempt > 3` 直接判 `failed`，不无限烧算力。

## 五、Worker 协议（4 个端点）

所有端点前缀 `/api/v1/worker/`，用 `X-Worker-Token` 头鉴权（token 明文只存哈希在 DB）。

### 1. `POST /claim` — 领任务（长轮询）

```jsonc
// 请求
{"worker_id": "pc-01", "capabilities": {"gpu": "RTX 4090", "vram_gb": 24, "max_minutes": 30}}
// 200：领到任务
{
  "task_id": "uuid",
  "lease_seconds": 90,
  "video_url": "https://oss...?Expires=...&Signature=...",   // 签名下载 URL，15 分钟有效
  "mask_url": "https://oss...?..." ,                          // 可选：预置 mask
  "params": {"bbox": [1472, 42, 388, 130], "mode": "auto"},
  "meta": {"duration_ms": 61000, "width": 1920, "height": 1080, "fps": 30}
}
// 204：25 秒内无任务（worker 立刻重新发起）
```

**原子领取 SQL**（这是全系统最关键的一行）：

```sql
UPDATE task SET status='leased', worker_id=?, lease_expires_at=NOW()+INTERVAL 90 SECOND,
       attempt=attempt+1, started_at=NOW()
WHERE id = (SELECT id FROM (SELECT id FROM task
             WHERE status='pending' ORDER BY created_at LIMIT 1) t)
  AND status='pending';
```

MySQL 用 `SELECT ... FOR UPDATE SKIP LOCKED`（8.0+）更简洁，代码里已按此实现。

### 2. `POST /heartbeat` — 心跳续租 + 进度

```jsonc
{"task_id": "uuid", "stage": "lama_apply", "progress": 0.42, "message": "1843/4428 帧"}
// 200 {"ok": true, "lease_seconds": 90}
// 409 {"ok": false, "code": "lease_lost"}   ← worker 必须立刻终止本地渲染
```

**`lease_lost` 必须让 worker 自杀当前进程**：否则算力白烧，且可能与新 worker 抢同一个输出对象。

### 3. `POST /complete` — 完成 + 指标

```jsonc
{
  "task_id": "uuid",
  "result_key": "results/<uuid>/out.mp4",
  "metrics": {"residual_max": 1.8, "gradient_p50_ratio": 1.02, "flicker_p90": 0.4, "all_green": true},
  "report_key": "results/<uuid>/report.json"
}
```

**幂等**：重复提交同一 `task_id` 返回 200 且不改状态（防网络重试导致重复扣分）。

### 4. `POST /fail` — 失败上报

```jsonc
{"task_id": "uuid", "error_code": "OOM", "error_message": "CUDA out of memory at frame 3000", "retryable": true}
```

`retryable=true` 且 `attempt <= 3` → 打回 `pending`；否则 → `failed` 并退还积分预扣。

## 六、核心数据模型

### `accounts.User`

`id, phone(unique,null), wx_openid(unique,null), nickname, avatar, created_at`

### `tasks.WorkerNode`

`id, name, token_hash, capabilities(JSON), status(online/offline), max_concurrency, last_heartbeat_at`

### `tasks.Task`（核心表）

| 字段                                                        | 类型           | 说明                   |
| --------------------------------------------------------- | ------------ | -------------------- |
| `id`                                                      | UUID         | 主键，同时是 OSS 路径片段      |
| `user_id`                                                 | FK           |                      |
| `status`                                                  | varchar(20)  | 状态机，加索引              |
| `original_key` / `mask_key` / `result_key` / `report_key` | varchar(255) | OSS 对象键              |
| `duration_ms` / `size_bytes` / `width` / `height` / `fps` | int          | 探测得到的元数据             |
| `params`                                                  | JSON         | bbox、方案提示            |
| `metrics`                                                 | JSON         | 验收指标（四项 + all_green） |
| `worker_id`                                               | FK(null)     | 当前/最后处理的 worker      |
| `lease_expires_at`                                        | datetime     | 租约到期                 |
| `attempt`                                                 | int          | 已领取次数                |
| `points_cost`                                             | int          | 预扣积分                 |
| `error_code` / `error_message`                            | varchar      |                      |
| `created_at` / `started_at` / `finished_at`               | datetime     |                      |

索引：`(status, created_at)`、`(user_id, created_at)`、`(lease_expires_at)`。

### `billing.PointLedger`（只增不改的账本）

`id, user_id, delta(±), balance_after, reason(sign_in/consume/refund/subscribe), ref_task_id, created_at`

**积分只用账本 + `balance_after` 快照，不做 UPDATE 覆盖**，避免并发扣成负数。

### `billing.SignInRecord`

`user_id, date, points, created_at`，唯一约束 `(user_id, date)`。

### `billing.Subscription`

`user_id, plan(monthly), status(active/expired), started_at, expires_at, minutes_used`

## 七、鉴权与凭证

| 凭证               | 存放位置             | 有效期   | 权限                                               |
| ---------------- | ---------------- | ----- | ------------------------------------------------ |
| 用户 token         | 浏览器 localStorage | 7 天   | 只能操作自己的任务                                        |
| **worker token** | 算力机 `.env`       | 长期    | 只能调 4 个 worker 端点                                |
| OSS 上传 policy    | 浏览器临时持有          | 15 分钟 | 只能 POST 到 `uploads/<uuid>/` 前缀，限大小与 content-type |
| OSS 下载签名 URL     | worker 内存        | 15 分钟 | 只能 GET 单个对象                                      |

**关键点：算力机不持有 OSS AK/SK**。它拿到的是云端**按对象签发**的临时 URL，泄露面仅限一个对象、15 分钟。

## 八、上传流程（OSS PostObject 直传）

```
① 浏览器 POST /api/v1/uploads/sign  {filename, size, content_type}
② 云端校验额度（时长/大小/积分）→ 建 Task(awaiting_upload) → 返回
   {task_id, host, policy, signature, key, accessid, expire}
③ 浏览器用 FormData POST 到 OSS（ali-oss 或原生 form）
④ 上传成功 → 浏览器 POST /api/v1/tasks/{id}/confirm  {duration_ms, width, height}
⑤ 云端校验对象存在（HEAD）→ 状态置 pending → 预扣积分
```

policy 限制：`content-length-range` 0~524288000（500MB）、`key` 必须匹配 `uploads/${task_id}/*`、`Expires` 15 分钟。

### 待处理风险：客户端直接调用 OSS

当前文件上传由浏览器直接请求 OSS，云端负责签发临时上传凭证并在确认任务时检查对象存在。客户端可绕过页面校验，使用仍有效的凭证直接上传；如果签名条件、对象键范围、文件大小或类型校验有遗漏，可能造成非预期对象写入、存储与流量费用增加，或上传内容与任务记录不一致。上传成功但未确认的对象也可能形成孤儿文件。

后续需专项核查签名权限与有效期、服务端对对象大小和类型等属性的复核、上传频率与额度限制，以及未确认对象的清理机制。此处先记录风险，不改变现有上传流程。

## 九、积分扣减时机

| 时点       | 动作                     | 理由             |
| -------- | ---------------------- | -------------- |
| 建任务      | **不扣**（只校验余额）          | 避免上传失败还要退      |
| 确认上传     | **预扣**（`consume`，负数条目） | 用户已消耗资源，必须有约束  |
| 成功       | 无操作（预扣即实扣）             |                |
| 失败（重试耗尽） | **退还**（`refund`，正数条目）  | 是我们的问题，不是用户的问题 |
| 用户取消     | 退还                     |                |

并发安全：扣减时 `SELECT ... FOR UPDATE` 锁住用户最新余额条目，写新账本行，`balance_after = prev + delta`，余额 < 所需则拒绝。

## 十、定时任务（cloud_web）

| 任务                       | 频率       | 作用                                    |
| ------------------------ | -------- | ------------------------------------- |
| `reclaim_expired_leases` | 30s      | 租约超时打回 pending / 判 failed 退款          |
| `expire_stale_uploads`   | 5min     | `awaiting_upload` 超 30 分钟 → `expired` |
| `cleanup_oss`            | 1h       | 删 24h 前的原片与成片（合规承诺：处理完即删）             |
| `reset_monthly_points`   | 每日 00:10 | 积分月度清零                                |

MVP 阶段用 Django 管理命令 + 系统 cron 即可，不引入 Celery（省一个 Redis）。规模化再换。

## 十一、独立部署

### cloud_web

```bash
cd cloud_web
cp .env.example .env        # 填 MySQL / OSS / 域名
docker compose up -d --build
docker compose exec web python manage.py migrate
docker compose exec web python manage.py createsuperuser
```

### gpu_worker

```bash
cd gpu_worker
cp .env.example .env        # 填 CLOUD_BASE_URL / WORKER_ID / WORKER_TOKEN / 脚本路径
docker compose up -d --build
docker compose exec worker python manage.py migrate
docker compose exec worker python manage.py run_worker    # 常驻主循环
```

**Windows 部署（豆豆的 PC 大概率是 Windows）**：推荐用 WSL2 跑 Docker；如果直装，把 `run_worker` 注册为「任务计划程序」开机自启，脚本路径用绝对路径（**Windows 下必须注意反斜杠与盘符**，`.env` 里用正斜杠 `C:/wm/scripts`）。
