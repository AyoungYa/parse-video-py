# video-remove-watermark

针对**烙进画面流的固定位置水印**（磨砂半透明卡片 + 白字 + 平台 logo，典型如
「微博视频号」← 微博 logo + 「@作者名」+ 视频标题）的定位与去除。
核心思路：**不猜、不人肉框选，用像素证据定位**，再分两档修复。

## 水印结构（微博横屏 1080P 实测）

```
┌──────────┐
│ ◎ 微博logo│  张睿  拿手好戏《悟空》     ← 第一行  y≈55-127
└──────────┘
        @张睿 关注                   ← 第二行  y≈133-168
 x≈1495-1583                          x≈1598-1864
```

**左边那枚微博 logo（环形 + 内瞳）是最容易漏的**——它比文字左界还靠左 100px，
一旦 bbox 左界收过头就被整枚切在 mask 之外。见坑 17。

## 修复方案选择（重要）

| 方案 | 工具 | 效果 | 速度 | 适用 |
|---|---|---|---|---|
| **LaMa AI 修复（推荐）** | `lama_remove.py` | 结构感知填充，修复区有真实纹理；**逐帧独立推理**，无印记 | 端到端 **1.65s/帧**（8 核 CPU，1080P 小 patch，`-threads 1`） | 高纹理/运动背景（舞台、人脸） |
| ffmpeg delogo | `remove_watermark.py` | 线性插值，复杂背景有涂抹感 | 实时 | 纯色/模糊背景，角落水印 |
| ~~白叠加 alpha 反解~~ | 自研 | 残留 +24~+33，肉眼可辨 | 实时 | **已否决，别用**（见下方实测档案） |


**用户实测结论（2026-10-14）**：舞台灯光视频上 delogo 涂抹感不可接受 →  
默认走 LaMa。delogo 保留给纯色背景场景（快）。

## LaMa 方案要点（lama_remove.py）

- **局部推理**：只裁水印 bbox 周边小图送 LaMa，修复后贴回原帧——生成式
  模型可能改整幅画面，局部化保证水印外像素 100% 原样
- **交付级 = 逐帧 LaMa（`--keyframe-every 1`）**：每帧独立修复，内容真实
  跟随画面。任何"关键帧 + 传播"的省算力做法都不行：
  - 光流 warp 是**负优化**——水印钉在屏幕空间，warp 会把干净修复区搬离
    水印位置、水印重新露出（实测残留从 0 涨到 2123-6298px/帧）
  - `blend_patch()` 静态贴回解决了露出，但**会留"印记"**（bbox 区贴的是
    关键帧旧内容 → 补丁冻结感 + 旧内容亮包，用户实测打回）
  逐帧模式代价：8 核 CPU 端到端 **1.65s/帧**（1080P 小 patch，`-threads 1`），
  3471 帧拆两半并行 **51.5 分钟**
- **流式管道**：ffmpeg 解码 → Python 逐帧 → ffmpeg 编码，**零临时帧文件**。
  旧版"先抽全部 PNG"在 1080P/3471 帧要 5-7GB×2，磁盘一紧就 ffmpeg exit 228
- **精确形状 mask（最优方案，用户思路）**：水印颜色固定（白字 + logo + 磨砂卡），
  用**时域最小投影**（白字恒亮，灯光间歇）+ 时域 std 提取水印的精确像素
  形状，LaMa 只重建水印真正覆盖的像素——bbox 内的移动灯光等画面完全不碰
  （实测 mask 外最大像素差 19 = 编码噪声级零干扰），修复面积只有矩形
  bbox 的 29%。`--mask-file watermark_mask_1080p.png`（已存 skill 目录，
  392×136）

- **bbox 必须覆盖完整水印结构**：微博水印是**两行**结构（主卡片 y≈66-126
  + UP主 ID 行 y≈135-190，中值帧会低估底边——单帧文字实际到 y=189）。
  **且左边还有一枚微博 logo 图标**（环形+内瞳，x≈1495-1583，y≈55-127），
  与文字之间隔约 15px 空白。**最终安全 bbox：`x=1484 y=44 w=392 h=136,
  pad=10`（1080P 横屏）** —— 见坑 17，左边界一旦收进 1590 就会把 logo
  整枚漏掉（logo 是白色，时域最小投影 207，跟白字同级，不是颜色问题）。
  bbox 底边卡在文字边缘时羽化带会残留半截文字；但**左边不要为了躲灯光
  而收窄到把 logo 切掉**（坑 15 与坑 17 是一对矛盾，正解见坑 17）
- 编码三步走（纯视频 → 抽原声 → 混流），避开 ffmpeg 双输入 seek 的坑
- LaMa 输出可能 pad 到 8 的倍数，贴回前裁回 crop 原尺寸
- 依赖 `simple-lama-inpainting`（**必须用 uv 装**，pip 会因 TMPDIR 冲突
  EEXIST 失败）；权重 `big-lama.pt` 200MB，GitHub 直连 502 时用镜像：
  `https://ghfast.top/https://github.com/enesmsahin/simple-lama-inpainting/releases/download/v0.1.0/big-lama.pt`
  放 `~/.cache/torch/hub/checkpoints/big-lama.pt`
- 1080P v5 全片实测（3471 帧 / 138.84s）：字形对比度 原片 +74.4
  （logo 区 +87.1 / 文字区 +70.8）→ 成片 **+0.6（logo 区 −0.4 / 文字区 +0.9）**；
  逐帧索引映射全程恒定偏移、**无丢帧/重帧**（含拆半拼接的接缝处）


```bash
# 交付级标准流程 (精确mask + 逐帧; mask 提取方法见下方)
python src/skill/lama_remove.py 视频.mp4 1484 44 392 136 --pad 10 \
  --mask-file src/skill/watermark_mask_1080p.png --keyframe-every 1 \
  --start 20 --duration 6    # 打样
python src/skill/lama_remove.py 视频.mp4 1484 44 392 136 --pad 10 \
  --mask-file src/skill/watermark_mask_1080p.png --keyframe-every 1 \
  --out 成片.mp4             # 全片

# 精确 mask 提取方法 (新视频需重做):
#   1. 扫描窗务必开大: x=1440 y=20 w=460 h=180 (含 logo 与余量)
#   2. 1fps 抽 200 帧全时段覆盖
#   3. 白字 = 时域最小投影(1% 分位) > 168 (恒亮=水印; 灯光间歇被剔除)
#   4. 卡底 = 时域 std < 30 ∩ 白字膨胀 21px
#   5. 形态学闭 7 / 开 3 清理 -> 按 bbox 裁剪存 PNG (白=修复区)
# 1080P 逐帧 ~1.65s/帧 (8 核, -threads 1); 138s 全片 3471 帧
#   单进程约 95 分钟 / 拆两半并行约 51 分钟; 流式管道零临时帧
# 拆两半并行 (可选加速):
#   ... --start 0 --duration 69.44 --out part_a.mp4
#   ... --start 69.44                --out part_b.mp4
#   ffmpeg -f concat -safe 0 -i list.txt -c copy silent.mp4
#   ffmpeg -i 原片 -vn -c:a copy a.aac && ffmpeg -i silent.mp4 -i a.aac \
#     -map 0:v -map 1:a -c copy -shortest 成片.mp4
```

**自检命令（无法用眼睛看图时的 ASCII 显形法）**：把候选区域逐块(4×4)降采样成
字符画，`chars = " .:-=+*#%@"` 按值 0-255 映射——水印字形会直接"画"出来，比看
指标快得多。配合**时域中值图**（60 帧中值）可以放大任何静态残留：修复后的
中值图若还能看出字形轮廓 = 没修干净。


## 什么时候用

- 视频下载后发现固定位置有平台水印（右上/左上/右下角的小卡片）
- 水印是**静态**的（全程位置不变）
- 水印底下是**运动画面**（舞台/人物/滚动内容）——这是时域定位的前提

**不适用**（别硬套）:

- 滚动字幕/漂移水印 → 需要逐帧跟踪，本 skill 不做
- 水印在纯色静止背景上（如 PPT 录屏）→ 时域法无信号，直接人肉给坐标
- GPU 不可用时超长视频（>5 分钟）的 LaMa 全片渲染要按 CPU ~0.3s/帧预算时间

## 定位原理（双通道联合 + 联合框）

- **通道 A · 帧间差图**：相邻帧 |diff| 的均值。磨砂/半透明叠加层把底下画面  
  变化抹掉一半以上 → **完整卡片**（含磨砂边框）在 D 图上是低值块
- **通道 B · 时域 std**：像素沿时间轴的波动。白字核心完全不透明 → **文字核心**  
  std 极低。两通道重叠 → 取并集框；仅 B 命中 → 按帧间差图自适应外扩补磨砂边
- **角窗扫描**：只在 4 个角窗（上/下 × 左/右）搜低值矩形连通域，天然排除  
  画面中央静止内容（字幕、文案排版）
- **验证**：位置恒定性（区域 vs 同高背景带时域 std 比）+ 结构置信度  
  （最大投影帧上白字锐度 vs 磨砂底/周边，分 high/normal/low 三档——  
  舞台强光视频锐度比拉不开，仅作参考不做硬过滤）

修复：`ffmpeg delogo`（矩形边框像素梯度插值填充）。

## 标准工作流（两个脚本串联）

```bash
# 1) 自动定位 (输出 bbox JSON; 注意自动定位只给主卡片行, 需人工补 logo 段)
python src/skill/remove_watermark.py 视频.mp4 --preview
# 2) 用定位到的 x/y/w/h 跑 LaMa 打样
python src/skill/lama_remove.py 视频.mp4 1484 44 392 136 --pad 10 \
  --mask-file src/skill/watermark_mask_1080p.png --keyframe-every 1 \
  --start 40 --duration 8
# 3) 人眼确认打样 -> 全片
python src/skill/lama_remove.py 视频.mp4 1484 44 392 136 --pad 10 \
  --mask-file src/skill/watermark_mask_1080p.png --keyframe-every 1 --out 成片.mp4
```


## 实测档案（校准用）

| 案例 | 画质 | 水印位置(全图坐标) | skill 定位结果 | 校验 |
|---|---|---|---|---|
| 竖屏个人号 720x1280 (ot=v) | 720P 顶格 | 单卡片 x=[451,711] y=[49,132] 261x84 | 手工分析基准 | delogo 白字1459→0 |
| 横屏综艺 1080p (ot=h) | 1080P | **横向三段**: 微博logo x=[1495,1583] + 主卡片行 x=[1601,1860] y=[66,126] + ID 行 y=[135,190] | 定位只抓到主卡片行（坑13） | **v5 全片 3471 帧**：字形对比度 原片 +74.4（logo区 +87.1 / 文字区 +70.8）→ 成片 **+0.6（logo区 −0.4 / 文字区 +0.9）** |

规律：**横屏总内容 x≈1495-1864 / y≈55-168**（logo 段 + 卡片行 + ID 行，段间
有 15px 空白），**竖屏是单卡片 84px**；宽度 260-390px，贴角。
最终安全 bbox（1080P 横屏）：`x=1484 y=44 w=392 h=136 pad=10` + `watermark_mask_1080p.png`。

**性能基线（8 核 Mac，`-threads 1`，bbox 392×136）**：
LaMa 单次 ~1.0s；端到端流式 **1.65s/帧**；3471 帧拆两半并行 **51.5 分钟**。
编解码器不限线程会恶化到 4.5s/帧（坑 21）。


**残留量化校验法（可复现的硬指标）**：对原片/成片各抽 60 帧同一组绝对时间点，
算时域中值图，再减去 41px 中值滤波得到的"局部背景基准"，在 mask 字形像素上
取平均 → 得到"字形对比度"。原片 +116 / LaMa 正确区 +1.4 / alpha 反解方案
+24~+33。**+1.4 是编码噪声级，可以交付；+24 以上肉眼可辨。**

**已否决：白叠加 alpha 反解 `C=(I-255a)/(1-a)`。** 数学上对"纯白半透明叠加"
是精确解且实时，但实测残留 +24（logo 区）/ +33（文字区），远不如 LaMa 的
+1.4。原因是水印并非严格的纯白均匀叠加（含半透明底与抗锯齿），alpha 标定
误差在 1/(1-a)≈5 倍放大下直接变成可见鬼影。**不要走这条路。**


## 已知坑（开发中实际踩过）

1. **窗口内坐标 vs 全图坐标**：角窗扫描拿到的是窗内坐标，组装 bbox 前必须  
   加回 `(xa, ya)` 偏移——曾因此把 delogo 修到画面中央、白字原地不动
2. **中值帧会抹掉白字**：高亮度波动视频（舞台灯光）里 60 帧中值把白字平均  
   掉了（实测 191 个 >220 像素 vs 最大投影 3549 个）→ 白字检测/锐度验证  
   一律用**最大投影帧**（`arr.max(axis=0)`）
3. **threshold 是场景相关的**：0.55 在两个实测案例都稳定；定位失败时脚本  
   自动降级重试（×1.18 收紧 / ×0.82 放松），还不行就人工指定坐标
4. **锐度比不能做硬过滤**：舞台视频背景本身亮且锐，白字/背景锐度比只有  
   3.2（竖屏案例 95 倍）→ 降为置信度参考（high/normal/low）
5. **时域 std 比的警告**：横屏综艺的「区域/背景 std 比」可能 >0.75  
   （实测 1.12 仍真水印）——恒定性验证只提示不拦截，最终以打样人眼确认
6. `delogo` 参数必须 ≥1 且不越画面边界，否则 ffmpeg 直接报错（已 clamp）
7. 抽帧用 PNG（JPG 压缩噪声污染 std 统计）；至少 8 帧且帧间要有画面变化
8. 磨砂卡片若盖在高纹理区（人脸特写），delogo 插值有涂抹感 → **此类场景直接
   走 LaMa**（delogo 定位功能照用，只是修复换 lama_remove.py）
9. 微博直链 1 小时过期（`Expires`/`ssig`），跨小时复用会 403，先重新解析
10. AgentEarth 的 `ae_image_editing_text_removal` API 连续 3 次任务 failed
    （PNG/JPG 都试过），别再浪费时间，本地 LaMa 更稳
11. ffmpeg 编码双输入时 `-ss` 放第二输入 + `-map 1:a` 会产出 261 字节空文件
    → 音频单独抽（`-vn -c:a copy`）再 `-c copy` 混流
12. **光流传播对固定水印是负优化**（v4 修复）：水印钉在屏幕空间，warp 修复
    结果 = 把干净区搬走、水印露出来。必须用静态贴回 `blend_patch()`
13. **中值帧会低估水印范围**：时域中值把半透明文字边缘平均掉了（实测
    中值帧显示水印到 y=179，单帧实际到 y=189）——确定 bbox 要用单帧
    极值或最大投影，并留 10-20px 余量
14. **校验时"亮像素残留"要先对照原片**：舞台灯光视频的灯光本来就在水印
    区闪（原片同区 8401 亮像素 > 成片 4362），不能只看成片亮像素数
    就判定残留
15. **bbox 别贪宽**：68s 案例中 bbox 左界 1480 圈进一条移动竖条灯光，
    静态贴回把它"冻结"在两帧间（凭空亮 6007px）——**但这是"静态贴回"的锅，
    不是宽 bbox 的锅**。逐帧 LaMa 下宽 bbox 无害（mask 稀疏，只修字形像素）。
    详见坑 17
16. **静态贴回会留印记（v2 打回，v3 修复）**：keyframe-every>1 时 bbox
    区域贴的是关键帧旧内容——画面运动时补丁"冻住"（冻结比 1.53）+
    旧内容亮包，肉眼可见明显印记。**交付级渲染必须 `--keyframe-every 1`**
    （逐帧独立修复，冻结比 0.94 与背景一致）；静态贴回只用于快速预览
17. **★ bbox 左界切掉微博 logo（用户两次打回的真根因）**：水印最左边还有
    一枚**微博 logo 图标**（环形 + 内瞳），位于 **x≈1495-1583**，比文字
    左界 1598 还靠左 100px。因为坑 15 把左界从 1480 收到 1590「躲灯光」，
    整枚 logo 被排除在 mask 之外 → mask 外零干扰，logo 也就零改动。
    **排查弯路警告**：现象是"logo 没去掉"，很容易误判成"logo 不是白色所以
    没被阈值捕获"，于是去查黄色/橙色/高饱和像素——全是白费。**正确第一步
    永远是：把扫描窗开大到 x=1440 w=460，看被裁掉的范围里有没有东西。**
    实测 logo 是白色的（时域最小投影 207，与白字同级），阈值从来没问题。
18. **磁盘满 → ffmpeg exit 228 / 编码失败**：旧版先把全片抽成 PNG（1080P
    3471 帧 ≈ 5-7GB）×2（输入+输出）。现已改为**流式管道**（ffmpeg 解码
    → Python 逐帧 → ffmpeg 编码），零临时帧文件。改之前先 `df -h` 确认。
19. **本机 LaMa 只在 `~/miniconda3/envs/parse-video-py/bin/python` 里**，
    项目的其它 venv（`~/Downloads/remove_mark_demo/.venv` 等）**没有**
    `simple_lama_inpainting`。跑之前先 `import` 探一下，别直接跑。
20. **看图能力受限时的替代手段**：无法读图时用「ASCII 显形法」（4×4 降采样
    → `" .:-=+*#%@"` 字符画）+「时域中值图」+「字形对比度"硬指标」三件套，
    能定位、能校验、能出量化结论，不必依赖肉眼。
21. **★ 编码器必须 `-threads 1`（最大的性能坑）**：x264 不指定线程时按
    `~1.5×ncpu` 自动开线程。在 8 核机器上跑 LaMa 时，编码线程会把 CPU
    从 LaMa 抢光——实测 `load average` 冲到 **48-60**，逐帧耗时从 2.2s
    恶化到 **4.5s**（且开 2 个并行进程也**完全没有收益**，8 核已饱和）。
    给编码器加 `-threads 1` 后回到 **1.65s/帧（2.7 倍提速）**。
    诊断信号：**如果 load average 远高于 ncpu，且单进程并不比双进程慢，
    就是编码线程在打架**。
22. **长片并行拆半的做法**：`--start 0 --duration 69.44` / `--start 69.44`
    两段并行，各自流式编码，最后 `ffmpeg -f concat -c copy` 拼接 + 单独
    抽原声混流。**验证接缝无丢帧/重帧的方法**：对成片若干帧号 i，在原片
    ±6 帧范围内找 `mean|Δ|` 最小的匹配帧号；若前后得到**恒定偏移**（如全程
    -3），说明帧序完整、无丢重。注意 `-ss` 在两文件上的精确寻址差异会带来
    恒定偏移假象，只要偏移**不跳变**即可放心。
